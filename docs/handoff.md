# Состояние работ и передача

Документ для того, кто продолжает работу. Описывает, что сделано, что
проверено, где лежат замеры и что делать дальше.

## Ветки

| Ветка | Состояние |
|---|---|
| `master` | основная линия: датапас, обфускация, пейсер, `brutal` с компенсацией потерь, `bbr` по мотивам quic-go, стенды `hysteria.sh` / `suite.sh` |
| `feat/fec` | FEC-слой (`src/tunnel.c`), ответвлён от старого `feat/bbr` до правок CC: перед слиянием с `master` нужно перебазировать и перепроверить, что FEC-пакеты не портят оценку потерь |

## Что сделано в `master`

### Контроль перегрузки

- `src/cc.c` — пейсер (token bucket + fq на 8 бакетов), debugfs-команды,
  общая оценка потерь.
- `src/cc_fb.c` — канал обратной связи CC_REQUEST/CC_FEEDBACK внутри
  data-пакетов (новых типов на проводе нет).
- `src/cc_brutal.c` — фиксированный шейпер с компенсацией потерь.
- `src/cc_bbr.c` — BBR (Startup/Drain/ProbeBW/ProbeRTT).

### Ключевые решения (не переоткрывать)

1. **Потери считаются по разности nonce**, а не по счётчикам, снятым в разные
   моменты. Иначе при 400 тыс. пакетов/с задержка обратной связи даёт до 80 %
   фантомных потерь.
2. **Дропы собственного пейсера исключаются** из оценки: отправитель кладёт
   свой счётчик `dropped` в CC_REQUEST, получатель возвращает его в
   CC_FEEDBACK.
3. **Пиковое окно 10 с** поверх окна доставки 2 с. Внутри туннеля может быть
   TCP, который сам является контроллером перегрузки; без длинного окна BBR
   принимает его кратковременный откат за сужение канала и складывается
   (проверено: 1.5 Гбит против 5.7 Гбит после правки).
4. **Очередь пейсера ~3 мс данных**, а не фиксированные 4096 пакетов.
   Глубокая очередь = bufferbloat, RTT внутреннего TCP растёт до миллисекунд,
   он сдаётся задолго до заполнения канала.
5. **Простой замораживает BBR**: без трафика тик не трогает фазы. Иначе
   startup выгорал за время настройки интерфейса.
6. **Старт BBR — из данных**: `init_cwnd / min_rtt` (32 * 1420 байт), а не из
   константы. `cc_rate` задаёт только нижнюю границу.

### Проверенные цифры (QEMU/KVM, 4 vCPU, изолированные ядра 8-11)

Хост шумит (рядом работают другие VM), разброс между прогонами до 2x.
Для сравнения конфигураций использовать интерлив (`suite.sh`) и медианы по
3 прогонам.

Без потерь, TCP 1420:

| режим | Гбит/с |
|---|---:|
| без CC | 4.7 |
| `bbr` | 5.8 |
| `brutal 4000` | 3.8 (шейпер) |

Без потерь, UDP 1340 при предложенных 4 Гбит:

| режим | Гбит/с принято | потери |
|---|---:|---:|
| без CC | 3.1 | 3.8 % |
| `bbr` | 2.4 | 4.2 % |
| `brutal 4000` | 3.0 | 3.4 % |

С потерями (netem 2 %, TCP 1420): все режимы 0.8-0.9 Гбит. Внутренний TCP
реагирует на потери сам, внешний CC их не скрывает — это задача FEC, не CC.
С 5 % потерь TCP падает до ~0.14 Гбит у всех режимов.

## Что дальше

1. **FEC** (`feat/fec`): стоимость доведена до 5-10 % при `k=16`, но схема
   `k data + 1 XOR` не спасает на 5 % потерь — нужен `m >= 2`
   (Reed-Solomon). Кандидаты на образец: FEC из Hysteria 1 (`klauspost/reedsolomon`),
   `kcp-go/fec.go`, UDPSpeeder (`lib/rs.cpp`, проще всего портировать в ядро).
2. Свести `feat/fec` с `master` (после CC) и перепроверить, что служебные
   FEC-пакеты не портят оценку потерь (сейчас в `master` их нет, в
   `feat/fec` — есть).
3. Сравнение с Hysteria 2 и AmneziaWG: `scripts/bench/suite.sh`.

## Стенд

```sh
# umbrawg с заданным CC
env UWG_CC="all bbr" ./scripts/bench/bench.sh umbrawg 0 tcp1420 4 3
env UWG_CC="all brutal 4000" UWG_UDP_BITRATE=4000 \
    ./scripts/bench/bench.sh umbrawg 0 udp1340 4 3

# все реализации интерливом
env UWG_REF_TOOL=/usr/bin/awg UWG_REF_KIND=amneziawg \
    UWG_REF_MODULE=amneziawg ./scripts/bench/suite.sh tcp1420 3 2 2

# hysteria2 отдельно
env HY_CC=brutal HY_BW="1 gbps" ./scripts/bench/hysteria.sh 0 tcp1420 4 3
```

Всё запускать только через `vm.sh` (QEMU/KVM, cgroup isolated), иначе
замеры бессмысленны:

```sh
sudo env BENCH_CPUS=8-11 ./scripts/bench/vm.sh vng --run --force-9p \
    --cpus 4 --pin 8-11 --memory 3G -- <команда в гостя>
```

## Грабли, на которые уже наступали

- `skb->cb` не обнуляется для пакетов из стека: всегда `memset` при создании
  skb и в `wg_xmit`.
- `PACKET_CB(first)->keypair` живёт только у головы списка, и голова
  освобождается при отправке — читать её в цикле нельзя (был UAF и паника).
- `hrtimer_setup()` вместо `hrtimer_init()` (7.3).
- `hrtimer_cancel()` под спинлоком — дедлок.
- `iperf3 -b` задаётся на поток: делить общую скорость на `FLOWS`.
- UDP мерить по `end.sum_received`, а не `end.sum` (второе — сторона
  отправителя, то есть предложенная нагрузка).
- `div_u64` берёт u32-делитель; для больших делителей — `div64_u64`.
